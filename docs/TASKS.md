## 3. Handoff

**넘겼으면 단톡에 한 줄 남깁니다.** 받는 사람이 기다리는 줄 모르면 그게 오늘 가장 큰 손실입니다.

| 넘기는 역할 | 산출물 | 받는 역할 | 전달 장소 |
|---|---|---|---|
| **1** (F1) | LMS Calendar 실제 응답 | **2** (F2) | 직접 전달 — **저장소에 커밋 금지** |
| **2** (F2) | raw 일정 JSON **샘플 1건** | **3** (F3) | Issue [#5](https://github.com/hyerin24/WhenWe/issues/5) 코멘트 — **개인 일정 제목 가림** |
| **3** (F3) | 공통 스키마 필드 | **4** (F4) · **7** (F7) | [api.md](api.md) — **필드명은 여기서 정하지 않음** |
| **4** (F4) | 실행되는 `backend` · 로그인·팀 API | **5** (F5) | 브랜치 push + 단톡 · 계약은 [api.md](api.md) |
| **4** (F4) | 팀 일정 조회 응답 형태 | **6** (F6) | [api.md](api.md) (CP2까지) |
| **3**·**4** | 정제된 일정 · 팀 조회 결과 | **7** (F7) | [api.md](api.md) |
| **7** (F7) | Heatmap용 결과 형태 | **6** (F6) | [api.md](api.md) (CP2까지) |
| **5** (F5) | 프레임워크 결정 · 실행되는 `frontend` | **6** (F6) | 브랜치 push + 단톡 |

> endpoint · 필드명 · DB 테이블 · 계산식은 **이 문서에서 정하지 않습니다.** 합의되면 [api.md](api.md)에 적고, 이 표는 "어디를 보라"만 가리킵니다.
> **실제 LMS 원문 HTML과 개인 일정 데이터는 어떤 경로로도 저장소에 커밋하지 않습니다.**

## 4. 통합 체크포인트 — 각 10분

전원이 손을 멈추고 모입니다. 길어지면 그 자리에서 끊고 담당자끼리 따로 잇습니다.

### CP1 — 오전

- [ ] Frontend 프레임워크 확정
- [ ] `frontend` · `backend` — `npm install` 후 실행됨
- [ ] F3 공통 일정 스키마 **최소** 합의 → [api.md](api.md) 기록
- [ ] 브라우저 → 서버 전달 API **최소** 계약 → [api.md](api.md) 기록

> **합의는 말이 아니라 [api.md](api.md)에 적히는 순간 끝납니다.** 말로만 정하면 오후에 서로 다르게 만듭니다.

### CP2 — 오후 중간

- [ ] 실제 일정 데이터가 **F1 → F2 → F3까지 흐른다** (1건이면 충분)
- [ ] `backend` ↔ `frontend` 연결에 필요한 **응답 형태가 [api.md](api.md)에 정리됐다**
- [ ] 역할 6·7이 **Mock을 실제 형태로 교체할 수 있다** (Heatmap·알고리즘 연결 준비)
- [ ] **막힌 사람이 있으면 이 자리에서 재배치합니다**

### CP3 — 저녁

- [ ] §5의 end-to-end 연결을 함께 확인
- [ ] 못 채운 항목과 남은 blocker를 단톡에 정리 → 내일 아침 첫 작업

> [api.md](api.md)의 나머지 `합의 대기` 항목은 **구현을 막지 않는다면 CP2까지 미뤄도 됩니다.** CP1은 위 4개만입니다.

## 5. 오늘 저녁 연결 상태

**기능이 완성됐는지가 아니라, 내일 발표까지 이어지게 연결됐는지**를 봅니다.
기능 완료 판정은 [FEATURES](FEATURES.md)의 완료 조건과 각 Issue 체크박스가 기준입니다 — 여기서 다시 판정하지 않습니다.

**Must — 이게 먼저입니다** ([SPEC §3](SPEC.md#3-must))

- [ ] `frontend` · `backend` 모두 **clone 후 실행된다**
- [ ] 실제 LMS 일정 **1건이 브라우저 → 서버 → DB까지 도달**했다
- [ ] 팀 **생성 → 초대 코드 → 참가**가 한 번 성공했다
- [ ] Heatmap이 **렌더링된다** (저녁 시점엔 Mock이어도 됨)
- [ ] 부담도·여유도가 **입력을 받아 결과를 낸다** (수치 정확도는 내일)
- [ ] [api.md](api.md)에 **실제 합의된 계약이 반영**됐다 (엔드포인트가 0개가 아니다)
- [ ] **내일 시연할 흐름이 한 번 통과**됐다 — 로그인 → 팀 참가 → 수집 → Heatmap
- [ ] 남은 **blocker가 단톡에 공유**됐다

**Should · Could는 위 Must가 end-to-end로 통과한 뒤에 손댑니다.** ([SPEC §4](SPEC.md#4-should) · [§5](SPEC.md#5-could))
**[SPEC §6 Won't](SPEC.md#6-wont-이번-범위에서-하지-않음) 항목은 오늘 작업하지 않습니다.** 여유가 생기면 Must 보강에 씁니다.
